# 04 State And Risk System

## 状态系统目标
状态表达必须稳定、统一、可复用。
相同含义的状态，在不同页面尽量不要换名字。

## 推荐状态层级

### 正常推进类
- 已完成
- 已通过
- 可推进
- 执行中

### 待处理类
- 待确认
- 待补充
- 检查中
- 待授权

### 风险提示类
- 部分异常
- 存在风险
- 即将逾期
- 待跟进

### 阻塞失败类
- 已阻塞
- 已失败
- 已逾期
- 不通过

## 颜色语义
- Success：已完成 / 已通过 / 正常
- Processing / Primary：执行中 / 当前阶段
- Warning：待处理 / 待确认 / 轻中度风险
- Error：阻塞 / 失败 / 逾期 / 严重风险
- Default：中性说明 / 弱状态

## 风险表达标准
风险不能只有一个红色标签，必须尽量包含：
- 风险等级
- 风险原因
- 影响对象
- 下一步建议

## 当前阶段要求
第一轮 UI 改造中，优先把状态表达做统一。
即使暂时不深改业务逻辑，也要先让用户能看懂：
- 当前处于什么状态
- 当前有没有风险
- 当前下一步是什么
