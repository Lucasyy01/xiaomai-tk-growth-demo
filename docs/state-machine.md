# 状态机设计（State Machine）

## 1. 设计目标
本文件用于约束一期 MVP demo 的核心状态流，服务于页面交互设计和 Codex 原型生成。

原则：
- 状态尽量少，但必须真实
- 每个状态都要能解释下一步动作
- 状态必须能映射到页面展示

---

## 2. 客户状态

状态：
- 待评估
- 可推进
- 待授信
- 可立项
- 服务中
- 已冻结/已停服

流转：
待评估 → 可推进 → 待授信 → 可立项 → 服务中 → 已冻结/已停服

页面承接：
- 客户准入页
- 授信审批页

---

## 3. 启动前检查状态

状态：
- 待检查
- 检查中
- 待补资料
- 已通过
- 已驳回

流转：
待检查 → 检查中 → 已通过
待检查 → 检查中 → 待补资料 → 检查中 → 已通过
待检查 → 检查中 → 已驳回

页面承接：
- 启动前检查页

---

## 4. 回款账户绑定状态

- 已绑定
- 已失效

未绑定 → 待校验 → 已绑定

## 7. 项目状态

- 待执行
- 执行中
- 待授权
- 待投放
- 待回款
- 已完成
- 已暂停

流转：
待立项 → 待执行 → 执行中 → 待授权 → 待投放 → 待回款 → 已完成
执行中 → 已暂停
待授权 → 已暂停
待回款 → 已暂停

- 项目工单详情页

状态：
- 待开始
- 进行中

- 已完成
- 已超时
- 已阻塞

待开始 → 进行中 → 待审核 → 已完成

待开始 / 进行中 → 已超时

## 11. 账单状态

流转：
待生成 → 待支付 → 已结清

---

## 12. 给 Codex 的状态展示原则
- 页面必须明确显示当前状态
- 每个状态都要能看出下一步动作
- 风险状态必须高亮：
  - 已冻结
  - 已超时
  - 已阻塞
  - 已逾期
  - 授权失效
  - 已失效
  - 不建议复投
- 项目工单页负责展示状态摘要
- 子页面负责展示状态明细
