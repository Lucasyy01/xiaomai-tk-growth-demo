# Page Skill - Customer Admission

## 页面定位
这个页面本质上不是普通客户列表，而是“客户准入判断页面”。
它要帮助业务快速判断：这个客户是否值得进入 TikTok 增长服务流程，以及当前优先级如何。

## 主要用户
第一用户：
- 销售
- 客户成功
- 商机筛选人员

第二用户：
- 管理者
- 项目负责人

## 页面主问题
用户进入页面后，最想快速知道：
1. 这个客户值不值得接
2. 当前状态如何
3. 为什么这样判断
4. 当前最大风险或缺口是什么
5. 下一步应该推进什么

## 页面成功标准
看完页面后，用户应该能完成以下判断：
- 判断客户是否继续推进
- 判断优先级高低
- 判断是否具备进入启动前检查的条件
- 判断有哪些关键缺口需要补齐

## 信息优先级
页面信息优先级应该是：

### 第一优先级
- 当前准入状态
- 商机评分 / 优先级
- 是否建议推进
- 下一步动作

### 第二优先级
- 关键判断依据
- 客户标签
- 风险 / 缺口项

### 第三优先级
- 客户详细背景
- 次级说明
- 辅助信息

## 页面结构建议

### A. 页面头部
展示：
- 页面名称
- 页面目标说明
- 当前筛选对象概况
- 当前状态标签
- 页面主操作，例如“发起启动前检查”

### B. 概览区
建议使用 4 张左右核心卡片表达：
- 当前准入状态
- 商机评分
- 风险数
- 下一步动作

### C. 主列表区
主列表应该更像“待判断客户池”，而不是普通信息列表。
建议优先用 Table 表达：
- 客户名称
- 评分
- 状态
- 核心标签
- 风险摘要
- 建议动作

### D. 详情区
点击某客户后，右侧或下方展示详情，重点表达：
- 判断依据
- 风险缺口
- 当前建议
- 是否可以进入启动前检查

### E. 风险与建议区
风险必须是可判断、可解释、可行动的。
不要只有“高风险”三个字，要说明：
- 风险来自哪里
- 影响什么
- 建议动作是什么

## 状态系统
建议优先使用：
- 可推进
- 待补充
- 高优先级
- 存在风险
- 不建议推进

## 页面不应该变成什么
不要把这个页面做成：
- 普通 CRM 客户列表
- 花哨的数据看板
- 只有评分但没有判断依据的概念页
- 没有下一步动作的展示页

## 第一轮 UI 改造目标
第一轮不深改业务逻辑，先做到：
- 页面更像成熟 SaaS
- 信息层级清楚
- 状态统一
- 风险和下一步前置
- 主列表更规范
- 详情区更可信
