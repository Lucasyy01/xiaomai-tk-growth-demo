# Page Skill - Startup Preparation

## 页面定位
这个页面不是一级菜单下的三个独立工作台，而是一个“启动准备”阶段页面。

它承接 CustomerAdmission 之后的连续流程，用于帮助业务确认：当前客户是否已经具备从准入判断进入正式项目推进的准备条件。

页面通过 3 个 Tab 组织启动准备阶段：
- 启动前检查
- 账户与扣款
- 授信审批

## 主要用户
第一用户：
- 客户成功
- 项目经理
- 交付负责人

第二用户：
- 销售
- 财务协同
- 管理者

## 页面主问题
用户进入页面后，最想快速知道：
1. 当前客户在启动准备阶段的总体状态是什么
2. 当前已经推进到哪一个子阶段
3. 哪个子阶段存在阻塞
4. 当前是否允许进入下一阶段
5. 下一步唯一应该做什么

## 页面成功标准
看完页面后，用户应该能完成以下判断：
- 判断当前客户是否仍处于启动准备阶段
- 判断当前卡在哪个 Tab 阶段
- 判断阻塞来自启动前检查、账户授权还是授信审批
- 判断下一步唯一动作是什么
- 判断是否可以继续进入项目工单阶段

## 信息优先级

### 第一优先级
- 当前客户是谁
- 启动准备总体结论
- 当前所在阶段 / Tab
- 当前阻塞状态
- 下一步唯一动作

### 第二优先级
- 当前 Tab 的关键结论
- 当前 Tab 的检查项 / 明细
- 当前 Tab 的阻塞原因和建议动作

### 第三优先级
- 补充说明
- 弱提醒
- 历史备注

## 页面整体结构建议

### A. 页面头部
展示：
- 页面名称：启动准备
- 页面目标说明
- 当前客户对象
- 当前总体状态标签
- 启动准备总体进度
- 返回 CustomerAdmission 的入口

### B. 总体摘要区
展示：
- 当前准备阶段结论
- 已完成阶段数 / 当前阶段 / 阻塞阶段数
- 是否允许继续推进
- 当前唯一主动作

### C. Tab 区
本页通过 3 个 Tab 组织启动准备流程：

#### Tab 1：启动前检查
回答：
- 当前客户是否具备启动条件
- 店铺准备、广告资产、归因准备是否到位
- 当前是否允许进入账户与扣款

#### Tab 2：账户与扣款
回答：
- 回款账户绑定是否完成
- 自动扣款授权是否完成
- 当前是否允许进入授信审批

#### Tab 3：授信审批
回答：
- 额度、账期、保证金和风险等级是否配置完成
- 当前是否允许进入项目工单

### D. 当前 Tab 内容结构
每个 Tab 内部都应保持轻量结构：
1. 当前 Tab 总体结论
2. 当前 Tab 分项明细
3. 当前 Tab 当前选中项详细说明
4. 当前 Tab 唯一主动作

## 动作系统
本页坚持：
- 页面层只有一个最重要的当前动作
- 当前 Tab 也只保留一个真正的主动作
- 不要在多个区域重复放置同等级 CTA
- 不要做一排流程推荐卡

## 页面不应该变成什么
不要把这个页面做成：
- 3 个复杂后台页硬塞进一个页面
- 流程说明页
- 培训页
- 多主按钮页面
- 大量解释模块堆叠页

## 第一轮 UI 改造目标
第一轮不深改业务逻辑，先做到：
- 启动准备作为一个阶段页成立
- 3 个 Tab 的关系清楚
- 每个 Tab 保持轻量
- 总体状态、当前阶段、阻塞项和下一步动作更清楚
- 页面比多个零散子页更连贯、更像成熟 SaaS
