# 04 Customer Portal Prompt

现在进入第四轮，只深做“客户轻门户”。

## 业务定位
这是客户视角的轻量协作页面，不是内部中台，也不是完整客户自助后台。

它的核心作用是：
- 让客户低成本理解项目当前进度
- 让客户查看需要自己确认的内容
- 让客户查看店铺 / 广告授权 / 回款账户 / 自动扣款状态
- 让客户查看账单与支付状态
- 让客户感受到平台流程透明、可信、可协作

## 页面目标
让客户一眼看懂：
- 我当前有哪些项目
- 每个项目现在在哪个阶段
- 哪些内容需要我确认
- 我的店铺和广告授权准备是否完成
- 我的回款账户和自动扣款授权状态如何
- 当前是否有待支付账单或异常提醒

## 页面承接对象
- 客户项目摘要
- 项目阶段摘要
- 待确认内容
- 店铺与广告授权状态
- 回款账户绑定状态
- 自动扣款授权状态
- 账单与支付状态
- 异常提醒

## 页面必须包含的区块

### 1. 我的项目概览
展示：
- 项目名称
- 项目类型
- 当前阶段
- 当前结果摘要
- 当前建议动作

要求：
- 项目卡片清晰
- 当前阶段要直观可见
- 点击项目可跳转到项目工单详情页（客户视角预览）

### 2. 待我确认内容
展示：
- 待确认脚本 / 样片 / 内容项
- 当前状态
- 截止时间
- 当前建议动作

要求：
- 这里只做轻量确认事项展示
- 不做复杂审核流
- 不做复杂编辑能力

### 3. 店铺与广告授权准备
展示：
- TikTok 店铺准备状态
- 广告账户授权状态
- TikTok 账号授权状态
- 当前待补充事项

要求：
- 明确哪些已完成，哪些未完成
- 明确未完成时会阻塞哪些流程

### 4. 回款账户与自动扣款状态
展示：
- 回款账户平台类型（如连连）
- 回款账户绑定状态
- 自动扣款授权状态
- 最近一次扣款结果
- 当前阻塞原因（如有）

要求：
- 明确表达这是平台对客户应收的自动扣款
- 不是 TikTok 原生广告扣费
- 若未绑定或未授权，要清楚表达影响

### 5. 账单与支付状态
展示：
- 待支付金额
- 已支付金额
- 最近账单状态
- 是否存在逾期

要求：
- 只做状态展示
- 不做真实支付动作
- 不做复杂账单编辑

### 6. 异常提醒与下一步建议
展示：
- 当前异常
- 风险提示
- 下一步建议动作

例如：
- 补充广告授权
- 完成自动扣款授权
- 查看待确认内容
- 查看账单详情
- 联系平台处理异常

要求：
- 页面不仅展示状态，还要让客户知道下一步该做什么

## 页面交互要求
- 点击项目卡片，可跳转或联动到项目工单详情页
- 点击待确认内容，可打开轻量详情
- 点击店铺/广告授权状态，可查看轻量说明
- 点击回款账户或自动扣款状态，可查看轻量详情
- 点击账单摘要，可跳转到账单回款页
- 不做真实确认提交
- 不做真实支付
- 不做复杂编辑

## 样式要求
- 与当前整体壳子风格一致
- 但比内部后台更轻、更友好、更克制
- 保持企业级可信感
- 状态和异常要清晰
- 不要做成复杂客户管理系统

## 数据要求
请基于现有 mock data 扩展客户轻门户所需数据，至少包含：
- 客户项目概览
- 待确认内容
- 店铺与广告授权状态
- 回款账户与自动扣款状态
- 账单与支付状态
- 异常提醒与下一步建议
