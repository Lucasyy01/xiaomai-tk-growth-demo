# 08 Payment Authorization Prompt

现在进入下一轮，只深做“回款账户绑定与扣款授权页”。

## 业务定位
这是客户回款账户绑定和自动扣款授权的前置页面，用来确认资金回收路径是否准备完成。

它不是支付中心，也不是财务系统。

## 页面目标
让用户一眼看懂：
- 当前客户是否已绑定回款账户
- 回款账户平台类型是什么
- 自动扣款授权是否完成
- 当前阻塞原因是什么
- 是否允许进入授信审批或继续推进

## 页面承接对象
- 回款账户绑定记录
- 自动扣款授权记录
- 账户状态
- 授权状态
- 当前阻塞原因
- 下一步动作

## 页面必须包含的区块

### 1. 页面头部
展示：
- 页面标题
- 页面说明
- 当前客户名称
- 当前整体状态

### 2. 回款账户信息区
展示：
- 平台类型（如连连）
- 账户标识摘要
- 绑定状态
- 最近一次校验结果

绑定状态至少包括：
- 未绑定
- 待校验
- 已绑定
- 已失效

### 3. 自动扣款授权区
展示：
- 授权状态
- 最近一次授权结果
- 当前说明
- 当前阻塞项

授权状态至少包括：
- 未授权
- 授权中
- 已授权
- 授权失效

### 4. 当前风险与阻塞区
展示：
- 当前未完成事项
- 未完成的影响
- 是否阻塞后续流程

### 5. 下一步动作区
展示：
- 进入授信审批页
- 返回启动前检查页
- 查看账单回款页
- 查看客户轻门户

要求：
- 明确表达“当前能不能继续推进”

## 页面交互要求
- 点击账户状态，可查看轻量详情
- 点击授权状态，可查看轻量详情
- 不做真实绑定
- 不做真实授权
- 不做复杂提交流程

## 样式要求
- 与当前整体壳子风格一致
- 状态和阻塞要清晰
- 重点是“绑定 + 授权 + 能否继续”

## 数据要求
请基于现有 mock data 扩展本页所需数据，至少包含：

- 账户绑定状态
- 自动扣款授权状态
- 当前阻塞原因
- 下一步动作建议
